# ANDROID-01 · Android 交付基线与真机验收计划

> 本文是 Android 端唯一权威计划，取代并删除原 `MOBILE-01.md`。
> 最后核对：2026-08-02；方法：源码与构建配置走查、CodeGraph 调用关系核对、`git ls-files`、TypeScript / ESLint / Vite 实跑。

## 1. 当前目标与范围

当前只做两件事：让核心创作闭环在 Android 真机上可靠可用，并建立可持续的安装、升级与构建链路。

- 核心闭环：项目 → 词条浏览/搜索/编辑 → AI 助手提议写入 → 差异审阅 → 落库与页面刷新。
- Android 交付：签名包、分发/升级路径、导入导出、权限与低端机基线。
- **本阶段不做高级功能**：快照/版本、关系图谱、世界地图、时间线、矛盾检测、角色对话。除非产品范围重新决策，否则不为它们补 Android 替代实现。
- Android 快照继续明确返回“暂不支持”：`snapshots_android.rs` 当前是统一 stub，Android 不编译 `git2`；本阶段不引入另一套版本存储。

## 4. P0 · AI 词条编辑差异审阅

| 任务 | 实现 | 真机验收 | 判据 |
|---|---|---|---|
| 在 `MobileApp` 全局挂载 `EntryEditModal` | ✅ `83546e0` | 🚧 | 下列 4 条真机链路全部通过 |

自动验证：

```bash
npx tsc -b
npm run lint
npm run build
```

真机使用“助手”模式验证，作家模式会绕过审阅：

1. AI 修改已有词条正文 → 出现差异审阅 → “应用全部修改” → 成功落库，详情查看态收到 `entry:updated` 后自动刷新。
2. 点“不应用” → 工具返回“用户取消了词条编辑确认”，数据库不变。
3. 安卓返回键 → 等价“不应用”。
4. 应用进行中（`busy`）按返回键 → 弹窗不关闭。

桌面端重复同一条链路，确认全局确认组件顺序没有引入回归。

### 差异弹窗真机观察项

先观察，命中判据才单独改；不要把适配猜测塞回 P0 挂载提交。

| 项 | 真机判据 | 命中后的最小处理 |
|---|---|---|
| 触控高度 | “上一处 / 下一处 / 展开全文”等按钮能否稳定点中 | 仅在 `max-width: 720px` 下补 `min-height: 44px` |
| 工具栏毛玻璃 | 截图中是否真的有毛玻璃 | 失效就换现有实色 token，不追祖先合成链、不新增模糊档位 |
| 弹窗高度 | 顶部或底部是否压住安全区 | 命中才把 `80vh` 改为 `80dvh` |
| 中文等宽排版 | Android 字体回退后 diff 行高是否错乱 | 命中才在移动 media query 调整字体栈 |
| hunk 计数 | 滚动时 `1/N` 是否更新 | 只能真机验；浏览器预览的 rAF / scroll 不可信 |
| 2000+ 行 diff | 展开全文后的滚动帧率和内存是否可接受 | 若失效，独立排性能任务，不并入本轮 |

## 7. P3 · 低端机性能基线

在扩大分发前选一台目标低端 Android 设备记录基线：

- 页面转场：连续 push / pop 与切 Tab 无明显掉帧或输入延迟。
- 长列表：大量项目、词条与 2000+ 行 diff 的滚动可用。
- 浮层 / 毛玻璃：无视觉失效；效果有问题优先降级为实色。
- WebView tile 内存：不恢复全局 `translateZ(0)` / `will-change`；若真机稳定复现纵向压扁，先做 tile 内存回归再定局部规避。

记录设备型号、Android / WebView 版本、数据规模和现象；没有基线数据，不做虚拟化或新的合成层优化。

## 8. 长期约束（从旧计划保留）

- 能力对齐，不照搬桌面布局；AI 是移动端结构化写入的重要入口。
- 顶部操作原则上不超过 3 个；低频操作进菜单，中高频操作保持可发现。
- 手势必须有按钮或系统返回键兜底；不可把功能藏成纯手势。
- 左屏幕边缘右划只表示返回；内容区横划用于本页侧边抽屉；横向滚动区域必须标记 `data-mobile-horizontal-scroll`。
- 页面交互嵌套原则上不超过 3 级，优先抽屉、分段与共享浮层，不继续压深页面栈。
- 浮层内容按需挂载、关闭即卸载；Android 返回键先走 `closeTopOverlay()`。
- 浏览器预览中 `document.hidden === true` 时 rAF 会挂起，scroll 事件也不会自然派发；滚动、hunk 计数、手势、权限和文件选择必须真机验收。
- 低端机优先：列表先分页，测到瓶颈再虚拟化；避免无依据引入重渲染或常驻合成层。
