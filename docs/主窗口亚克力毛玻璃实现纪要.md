## 一、本次会话做了什么

1. **梳理桌面端"三栏嵌入式工作区"架构**：确认外壳 `DesktopApp` 的 `top-bar + main-content(workspace-content + 右侧 side-bar)` 结构，以及"外层 chrome 用第二背景色 `--fc-color-bg-secondary`、内容卡片用 `--fc-color-bg` 并以 `1px solid var(--fc-color-border)` 分隔"的嵌入式范式（`.page-container` / `ProjectEditor` 的 `.pe-content` / `DockableSidePanel` 浮动卡片三处复用）。
2. **评估主窗口是否具备毛玻璃条件**：窗口透明前置条件已满足，但毛玻璃效果未实现，且被不透明 CSS 背景挡死。
3. **落地 Windows 亚克力(acrylic)毛玻璃**：声明式 `windowEffects` + 前端透明链路 + CSS 半透明着色，按平台门控降级。

## 二、讨论结论（决策记录）

### 1. 现状评估

| 条件 | 改动前状态 |
|---|---|
| 窗口透明 `transparent` | ✅ 已开（`tauri.conf.json`） |
| 无边框 `decorations` | ✅ 已关 |
| OS 背景模糊（acrylic/mica/blur） | ❌ 无 `windowEffects`、无 `window-vibrancy` 依赖、Rust/JS 均无调用 |
| Webview 根背景透明 | ❌ `body` / `.app-layout` 均为不透明 `--fc-color-bg-secondary`，会盖死模糊层 |

### 2. windowEffects 还是 CSS 实现毛玻璃

**结论：要"透出真实桌面"，只能用系统级 `windowEffects`（acrylic），CSS 做不到。**

- CSS `backdrop-filter: blur()` 只能模糊**同一文档内该元素背后已绘制的内容**；桌面壁纸/其它窗口由 OS 合成器在 webview 之外叠加，webview 取不到那层像素。对透明窗口直接用 `backdrop-filter` 只会看到**未模糊的桌面**。
- 分工：**窗口透出桌面 → 原生 windowEffects；应用内面板/弹窗叠加 → CSS `backdrop-filter`**（项目已在用，如停靠面板顶栏、封面遮罩）。二者互补。
- acrylic vs mica：acrylic 是真磨砂、模糊桌面+其它窗口，代价是 Windows 上拖拽/缩放有掉帧；mica 顺滑省电但偏淡、不模糊其它窗口、且不能自定义颜色。要毛玻璃质感选 acrylic。

### 3. 颜色控制

- mica 不能自定义颜色（仅跟随壁纸 + 亮/暗）；acrylic/blur 的 `color` 字段可着色，**但 Schema 注明该字段在 Windows 11 上无效**。
- 因此采用**混合方案**：acrylic 只负责"糊桌面"，颜色交给叠在其上的**半透明 CSS 层**。透明窗口下 webview 的半透明像素由 OS 合成在 acrylic 之上，CSS 的纯色即把模糊层染成主题色。
- 该方案契合现有 light/dark/system + CSS 变量体系，主题切换基本不用回 Rust。

### 4. 性能

- 原生 acrylic 由 DWM（系统合成器）在 GPU 上做，复用其本就在进行的桌面合成；CSS blur 在 webview 合成器内额外加 pass、之后还要再被 DWM 合成一次。做"糊桌面"原生更省，且只有原生能做。
- 粗略：**mica < acrylic < CSS blur（大面积/多层/背后内容在动时）**。
- **关键**：本次 CSS 部分是 `color-mix(... transparent)` 半透明**纯色填充**（alpha 混合，近乎零成本），**不是** `backdrop-filter`，因此当前实现没有为桌面磨砂付任何 CSS 模糊代价。
- 内容卡片不透明、磨砂只出现在少量 chrome 区，DWM 对被遮挡区域不重算，acrylic 开销随"可见透明面积"走，本就低。

### 5. 跨平台

| 平台 | `windowEffects:["acrylic"]` | CSS 透明链门控 | 结果 |
|---|---|---|---|
| Windows | 生效 | 命中 | ✅ 毛玻璃 |
| macOS | 不适用，被忽略 | 不命中 | 原样实色，无效果、无破坏 |
| Linux | 不支持，被忽略 | 不命中 | 原样实色，无效果、无破坏 |

- macOS 需改用 NSVisualEffect 材质（如 `under-window-background`/`sidebar`/`hud-window`）并为 `os==='macos'` 增设门控分支；当前 bundle 目标为 `nsis/deb/appimage`，未发 mac 包。
- Linux 无统一窗口模糊 API，效果取决于用户合成器，**原生毛玻璃实际不可行**，保持实色是正确选择。

## 三、落地改动（4 个文件，零 Rust 改动、零新依赖）

1. **`app_main/src-tauri/tauri.conf.json`**：main 窗口新增
   ```json
   "windowEffects": { "effects": ["acrylic"] }
   ```
   在已有 `transparent:true` / `decorations:false` 基础上开启 DWM 亚克力。未设 `color`（Win11 无效，着色走 CSS）。

2. **`app_main/src/main.tsx`**：在确认平台后写入门控属性——
   ```ts
   if (isTauriRuntime() && platformInfo.os === 'windows' && platformInfo.formFactor === 'desktop') {
       document.documentElement.setAttribute('data-backdrop', 'acrylic')
   }
   ```
   非 Windows / 移动端 / 浏览器都不命中，保持原实色（降级安全）。

3. **`app_main/src/App.css`**：在 `[data-backdrop="acrylic"]` 门控下——
   - `body` 透明；`.app-layout` 铺一层半透明主题色 `--fc-backdrop-canvas`（默认 `color-mix(in srgb, var(--fc-color-bg-secondary) 72%, transparent)`）。
   - 其余外层 chrome（`.top-bar` / `.main-content` / `.workspace-content` / `.pe-layout` / `.pe-tree-panel`）透明，避免叠加加深。
   - 组件库外层：`.fc-sidebar.side-bar` 背景透明（用 `(0,3,0)` 特异性稳压组件库 `[data-theme=dark] .fc-sidebar` 的同级背景）；`.fc-tab-bar` 的 `--tab-bar-bg: transparent`（其背景唯一来源，`--floating` 变体不另铺底）。
   - 内容卡片（`.page-container`、`.pe-content` 内部堆叠）维持实色，保证可读。

4. **`app_main/index.html`**：内联关键 CSS 增加 `html[data-backdrop="acrylic"] body{background:transparent}`，避免 App.css 加载前的启动底色盖住磨砂层。

效果分布：磨砂桌面透出在**顶栏标签栏、右侧图标栏、内容卡片四周间隙、左侧树栏**；内容卡片悬浮其上保持实色。

## 四、验证

- `tauri.conf.json` JSON 合法，`windowEffects` 结构正确，`transparent/decorations` 未受影响。
- `npm run lint`：0 error（唯一 warning 属无关旧代码 `MapShapeEditorWorkbench.tsx`）。
- `npx tsc --noEmit -p tsconfig.app.json`：0 error。
- CSS 改法已对照 `flowcloudai-ui/dist/index.css` 的真实定义核对。
- **未做真机视觉验证**：acrylic 由 OS 合成器渲染，网页预览看不出，需 `npm run tauri -- dev` 在真实 Windows 桌面确认。

## 五、可调参数

- 磨砂浓淡：`app_main/src/App.css` 中 `--fc-backdrop-canvas` 的 `72%`，越低越透出桌面、越高越实。

- 跨平台分流（Windows acrylic / macOS NSVisualEffect / Linux 保持实色）尚未实现，待需要 mac/Linux 磨砂时补充。
