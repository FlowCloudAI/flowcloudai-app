# ADR 0005：页面节点身份与公共组件序列化契约

- 状态：接受；页面文档契约 v1 的节点身份规则与公共组件格式已实现
- 日期：2026-09-18
- 关联：[ADR 0004](0004-unified-object-layer-and-asset-scope.md) 的受控引用、统一对象层与层叠顺序；公共组件的存储、展开和编辑流程仍属于阶段 D

## 背景

页面节点身份同时服务于段落索引、节点级引用、撤销历史、复制粘贴和后续语义合并。公共组件又要求页面只保存定义引用与实例配置，而不是把展开后的内部 DOM 当成页面节点。两者若只靠各编辑入口约定，会在源码编辑、AI 候选或跨文档粘贴时产生重复身份和失效引用。

阶段 A 因此冻结两项页面文档契约 v1 不变量：节点身份如何保持或重映射，以及引用式公共组件在 HTML 中如何表示。实现位于 `src/features/page-document/domain/kernel/contracts/` 与 `domain/kernel/syntax/`；真实保存准备路径会在校验前规范化受管节点身份。

## 决策

### 1. 节点身份规则

页面节点以 RFC 9562 UUID 形式的 `data-fc-node-id` 标识，并以 `data-fc-node-kind` 声明种类。节点 ID 在单个文档内唯一；跨对象引用使用对象 ID 与节点 ID 的组合。

| 场景 | v1 规则 |
| --- | --- |
| 保存、撤销、重做 | 未修改节点保留 ID；撤销恢复原 ID，重做沿用同一次操作的身份 |
| 可视编辑与源码编辑 | 内容修改不换 ID；新增节点分配新 ID；保存准备为缺失 ID 的受管节点补宿主生成的 ID；重复 ID 保留文档顺序中的第一个，其余分配新 ID 并给出警告 |
| 拆分与合并段落 | 拆分时前半保留原 ID，后半使用宿主分配的新 ID；合并时保留前一节点 ID，并把指向被并入节点的引用改指保留节点 |
| 同文档复制粘贴 | 复制分配新 ID；剪切移动保留原 ID |
| 跨文档粘贴 | 无论来源是复制还是剪切，全部分配新 ID |
| AI 候选 | 未修改节点保留 ID；新节点只接受宿主预分配的 ID；重复 ID 或既有 ID 与节点种类不符时拒绝候选 |
| 组件实例 | 实例根是页面节点；`data-fc-instance` 使用与页面节点 ID 不同的独立 UUID；组件内部节点不进入页面节点身份体系 |
| 转为本地组件 | 展开的内部节点全部分配新的页面节点 ID；实例 ID 退役；指向实例根的引用改指展开后的根节点 |
| 删除节点 | ID 进入退休集合且不得复用；节点级引用降级为对象级引用，并标记为 degraded |

身份生成由宿主负责。页面源码、iframe、AI 或外部载荷可以携带既有身份，但不能自行声明一个被当作可信新身份的 UUID。保存前的缺失与重复身份修复只做最小源码补丁，其余 HTML 保持原字节顺序。

### 2. 公共组件实例格式

公共组件实例是 `data-fc-node-kind="component"` 的页面节点，采用下列稳定属性：

```html
<div
  data-fc-node-id="<页面节点 UUID>"
  data-fc-node-kind="component"
  data-fc-component="<组件定义 UUID>"
  data-fc-component-revision="latest"
  data-fc-instance="<实例 UUID>"
  data-fc-prop-emphasis="true"
  style="--card-accent: CanvasText"
>
  <span data-fc-part="avatar">实例内容</span>
</div>
```

- `data-fc-component` 指向组件定义 UUID。
- `data-fc-component-revision` 为 `latest` 或正安全整数。格式允许固定修订，但是否在界面公开固定操作由阶段 D 决定。
- `data-fc-instance` 在单个页面文档内唯一，并与页面节点 ID 分离。
- `data-fc-prop-<name>` 逐项保存公开属性；名称使用小写短横线格式，不把所有配置塞进一个 JSON 属性。
- `data-fc-part="<name>"` 标记实例提供的插槽内容；名称使用小写短横线格式，同一实例内唯一。
- 实例样式变量覆盖沿用现有行内自定义属性规则；阶段 D 展开实例时再按组件定义的公开变量集合校验。
- 组件实例内部不得再声明页面节点身份；展开后的组件内部结构由组件定义及修订解释。

组件默认 CSS 位于 `fc-component` 层，只接受以 `[data-fc-component=` 开头的选择器。`fc-author` 仍不向作者写入开放。

### 3. `data-fc-part` 与 `data-fc-slot` 分工

`data-fc-part` 属于组件实例，其唯一性范围是最近的组件实例。同一页面上的多个组件实例可以各自包含 `avatar`，因为解析时以实例身份限定作用域。

`data-fc-slot` 属于项目默认模板，用于模板版本变更时比对命名坑位，因此在整份项目模板中保持全局唯一。两者不能共用一个属性或唯一性规则，否则重复插入组件会与模板合并契约冲突。

### 4. 公共组件定义格式

组件定义按修订保存，其运行时契约包含：

| 字段组 | 内容 |
| --- | --- |
| 身份与修订 | 组件 UUID、正整数 revision |
| 源码 | HTML、CSS |
| 公开接口 | 属性 schema、part schema、样式变量 schema |
| 资源 | 去重后的资产 UUID 依赖、可选 `image/webp` 预览资产 |
| 展示元数据 | 名称、分类 |
| 归属 | 开放字符串种类与范围 ID；0.2.0 只提供项目范围构造器 |

契约解析拒绝缺失字段、未知字段、重复 schema 名、非法名称、非法 revision 和非 WebP 预览。归属种类不在类型或数据库中封闭枚举；领域服务只授权当前已实现的项目范围。

### 5. 文档版本保持为 1

本次不提升 `DOCUMENT_VERSION`。已有 v1 文档不包含 `component` 节点也仍能按原规则解析；新增的是一个受控节点种类及只在该种类上生效的属性，没有改变既有元素或属性的含义。节点身份规范化补齐的是 v1 已要求的受管身份，不会把旧合法源码解释为另一种结构。

后续若改变已冻结属性的含义、让旧 v1 源码失去可解析性，或需要对现有组件实例做结构迁移，必须提升文档版本并提供迁移。只增加新的可选受控节点种类时，仍需逐项判断兼容性，不能据此永久沿用 v1。

## 后果与边界

- 保存准备可以确定性修复缺失或重复节点 ID，诊断可追溯，未触及的源码保持不变。
- 复制、合并、删除、AI 与组件本地化可共享同一身份规划函数，引用层能收到明确的重映射或降级结果。
- 页面已经能校验和保全公共组件引用格式，探针也能验证同名 part 的实例作用域。
- 阶段 A 只冻结格式与规则。组件定义的数据库存储、修订发布、宿主展开、缺失态、组件面板、实例属性编辑、影响范围提示、转为本地组件操作、依赖检查与世界包携带组件仍由阶段 D 实现。
