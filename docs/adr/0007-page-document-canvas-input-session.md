# ADR 0007：画布输入会话的一致性契约

- 状态：待评审；第一阶段只交付本契约与可执行的事件序列测试，不替换运行时
- 日期：2026-09-22（同日按第二轮评审重写：内容版本取代 `changeVersion`，明确纪元操作，补充终态消费确认、屏障对重放的约束、选区动作次序、撤销等待缓冲、恢复记录与桥会话生命周期）
- 关联：[ADR 0003](0003-page-document-canvas-isolation.md) 的 bridge 协议；[ADR 0005](0005-page-document-node-identity-and-component-contract.md) 的节点身份规则；[ADR 0006](0006-page-document-caret-and-inline-format.md) 的光标权威、行内格式、插入点锚点与末行占位

## 背景

ADR 0006 解决了「待输入标记归谁管理」，但一次输入从产生到落入文档的完整生命周期没有被设计过。文字依次经过输入法原生 DOM、画布乐观 DOM、内核提交后重新生成的预览；组合提交先还原组合前节点再重新插入；预览回来后整棵替换画布。内容、格式、焦点与光标要在这些交接中保持一致，而此前的做法是按症状追加推迟预览、丢弃暂存预览、拆块围栏与超时重放。

这些补偿依赖未经契约保证的假设，代码中可见的证据：

1. **预览与输入回执没有版本关联。** 预览只有 `requestId/html/css`，回执只有 `intentId/accepted/selection`，消息 `sequence` 只表示通道顺序。「成功回执到达时暂存预览必然早于该次提交」是对当前宿主调度的观察，不是协议保证（`canvas/runtime/resolvedSelection.ts` 的 `settleCanvasInputRender`）。
2. **拒绝后原样重放不成立。** 权威文本 `ab`，输入 1 在偏移 1 插入 `X`（得 `aXb`），输入 2 在偏移 2 插入 `Y`（得 `aXYb`）。若输入 1 被拒、输入 2 仍待处理，在 `ab` 上原样重放输入 2 得到 `abY`；由于折叠范围的 `expected` 是空字符串，现有范围校验（`application/canvasInputOperation.ts` 的 `applyCanvasInputToText`）仍然通过。
3. **拆块围栏在超时后按当时的光标与当时的格式重放**（`canvas/runtime/structuralInputFence.ts` 与 `main.ts` 的重放逻辑）。
4. **宿主在接收时就到已提交源码中查找输入目标**（`hooks/useEntryPageDocumentSession.ts` 的 `applyCanvasInputIntent`），依赖尚未提交之结构的输入必然被拒。
5. **现有 `changeVersion` 不能充当预览版本。** 以合法的 `data-fc-bind="title"` 夹具调用 `updateEntryDocumentMetadata`，`changeVersion` 保持不变而预览标题已改变；`loadLatestEntryDocument` 经状态创建函数使其归零（第二轮评审实测，本文核对代码确认）。
6. **桥会话令牌由 `[documentKey, projectId]` 决定**（`canvas/host/PageDocumentCanvas.tsx`），与画布运行时的启动次数无关。

现有测试多为单个状态对象的调用、队列的入队出队或源码字符串匹配，没有覆盖事件交错。

## 决策

采用「权威快照 + 本地重放」。宿主是唯一权威；画布挂载宿主快照后，把尚未被已挂载基线覆盖、且依赖仍然成立的本地编辑动作按序重新施加。以下各节是正确性契约，第一阶段须以事件序列测试证明。内核不改动。

### 1. 身份与版本

| 名称 | 规则 |
| --- | --- |
| 桥会话 | 画布运行时每次启动都建立新的桥会话。会话标识由现有令牌与**运行时实例标识**组成：实例标识在画布启动时生成并随首条消息上报，宿主据此为该会话重新建立序号、待处理记录、终态记录与保留 ID 池。旧实例的序号与消息一律不得进入新会话 |
| 文档纪元 `epoch` | 宿主会话状态被重新创建时递增：首次载入、切换文档、冲突后「载入最新版本」（`loadLatestEntryDocument`） |
| 内容版本 `version` | 由新的宿主会话层维护，纪元内严格递增。**凡权威预览（HTML/CSS）或草稿源码发生变化即推进**，判定依据是二者的内容，而不是枚举调用点；因此元数据绑定（如标题）、资产与组件定义等不经 `changeVersion` 的变化同样推进版本。不使用 `changeVersion` |
| 版本来源 | 每次推进都记录来源：画布输入（附 `seq`）或宿主变更（第 8 节） |
| 编辑动作序号 `seq` | 画布在桥会话内为每个编辑动作分配，严格递增 |
| 水位线 `watermark` | 宿主已按序处理完的最大 `seq`；不大于水位线的每个动作都已有终态 |
| 终态 | `accepted`（写入草稿，或宿主确认为无变化的历史动作）、`rejected`（所在批次未通过内核或宿主校验，或历史动作无可执行内容）、`cancelled`（依赖失败，未交给内核） |

一份快照由 `(epoch, version)` 唯一标识；同一标识必须对应相同的 HTML/CSS 与草稿源码。水位线相同的两份快照仍可能对应不同内容，画布不得只凭水位线判断新旧。

### 2. 编辑动作记录

画布输入一律规范化为编辑动作：插入文字、删除（按展开后的范围）、换行、拆块、粘贴、组合提交、撤销、重做。每个动作在产生时锁定，之后不再读取「那时的光标」或「那时的格式」：

- `seq`、动作类型、目标节点、`from/to/expected`、文字；
- 当时的待输入标记快照；
- 拆块动作的 `newNodeId`（第 7 节）；
- 依赖基线 `base = {epoch, version, watermark}`：产生时画布已挂载快照的版本与水位线。

组合提交的目标、偏移、格式与依赖基线在组合开始时锁定，组合结束时只补上最终文字与 `seq`。

画布另行记录**选区动作**（指针落点、方向键移动等作者手势），它们不发往宿主，但与编辑动作排在同一次序中（记录其之前最后一个编辑动作的 `seq`），用于第 9 节。

### 3. 依赖规则（宿主判定）

编辑动作 `n` 可以交给内核，当且仅当同时满足：

1. `base.epoch` 等于当前纪元；
2. 自 `base.version` 以来的每一次版本推进，来源都是 `seq` 位于 `(base.watermark, n)` 区间内、终态为 `accepted` 的画布动作；
3. 该区间内没有 `rejected` 或 `cancelled` 的动作。

否则 `n` 的终态为 `cancelled`，不交给内核。直观地说：画布算出 `n` 的偏移时所看到的文档，必须恰好等于宿主处理 `n` 之前的草稿。规则是保守的：任何宿主变更都使跨越它的依赖失败，按节点细化留待以后。

补充规则：

- 目标节点的存在性在按序处理时校验，不在接收时校验。
- 同一内核请求中的动作是原子批次，终态相同；批次被拒则整批为 `rejected`，不得只确认其中一部分。
- **本轮不引入通用位置重算。** 依赖失败的动作停止自动提交，转为第 6 节的恢复记录。

### 4. 快照与终态交付

快照取代现有 `render` 命令，字段为：`epoch`、`version`、`watermark`、`lastForeignVersion`（本纪元内最近一次宿主变更产生的版本）、`outcomes`、`html`、`css`，以及仅用于宿主变更的可选 `landing`。

**终态交付带消费确认。** 宿主保留画布尚未确认消费的全部终态；每份快照携带其中与本快照水位线一致的部分（尚未确认、且 `seq` 不大于水位线的全部终态）。画布先把终态写入按 `seq` 连续、可去重的接收记录，再决定是否挂载，然后回报已连续消费到的 `seq`；宿主收到确认后才裁剪。通道先进先出只保证顺序，不替代消费确认；同一终态重复到达按 `seq` 去重。

**区分已收到的进度与已挂载的基线。** 接收记录只说明终态已知；已挂载基线是画布当前 DOM 所对应快照的 `(epoch, version, watermark, lastForeignVersion)`。`seq` 大于已挂载水位线的编辑动作一律保留在重放集合中，即使其 `accepted` 终态已经收到，因为当前 DOM 尚不包含它。

画布接纳规则：

| 情况 | 处理 |
| --- | --- |
| `epoch` 更新 | 重放集合全部转为恢复记录，挂载新快照 |
| 同纪元、`version` 更大 | 挂载并重放（第 5 节） |
| 同纪元、`version` 相等 | 不重挂 DOM，但必须推进会话状态：消费终态、推进已挂载水位线、结算重放集合、解除撤销等待、应用 `landing`；若重放集合中有动作被拒或取消，在已挂载快照上重建并重放其余动作 |
| 同纪元、`version` 更小，或水位线回退 | 协议违例：不挂载，记录诊断；其中终态仍写入接收记录 |
| 组合进行中 | 只写入接收记录，保留最新快照；组合结束后再挂载 |

「不重挂 DOM」不等于「不更新基线」。例如撤销栈为空时，宿主必须仍发出版本不变、携带该撤销动作终态的快照，画布据此解除等待。

### 5. 重放

挂载快照 `S` 后，按 `seq` 顺序重放 `seq > S.watermark` 的编辑动作 `n`，当且仅当：

1. `n.base.epoch = S.epoch`；
2. `n.base.version ≥ S.lastForeignVersion`，即 `n` 产生之后没有宿主变更；
3. 接收记录中，`(n.base.watermark, n)` 区间内没有 `rejected` 或 `cancelled` 的动作。

这与第 3 节是同一规则在画布侧的投影。例如旧底稿上的动作尚在传输，宿主先替换源码并发来新快照：此时没有任何失败终态，但第 2 条不满足，画布不得把旧偏移重放到新源码上；宿主稍后收到该动作也将判为 `cancelled`。

不满足条件的动作不重放，转为恢复记录。重放使用动作记录中的格式快照；挂载与重放在同一任务中完成。同步完成只保证不画出中间状态的 DOM，**不作为「不闪烁」的证明**。

### 6. 恢复记录

`rejected` 与 `cancelled` 的编辑动作从画布撤下，并写入宿主会话层的恢复记录。记录不是一次性提示，不因重挂或纪元变化消失，字段包括：文档归属（词条标识）、纪元、动作次序、动作类型、文字、格式快照、原目标与偏移、失败原因、处理状态。

- 同一次失败连带的动作归为一组。只有当该组动作在其原始底稿上按序施加后恰好等价于「在一处插入一段文字」时，才提供可插入的文字；否则显示「操作未执行」并列出动作。「输入一个字再删除」的失败序列等价于无变化，不得拼成那个字供恢复；删除、拆块、换行等没有可插入文字的动作显示「操作未执行」。
- 「插入到当前光标」生成一条全新的、经完整校验的编辑动作，以当前已挂载基线为依赖；该动作被接受后才把记录标为已恢复，失败则保持原状并说明原因。
- **禁止静默删除，禁止自动改投。**

最小界面为非阻塞提示与可重新打开的恢复列表，提供复制与「插入到当前光标」。

### 7. 结构身份与乐观拆块

- 宿主会话层按 `(桥会话, 纪元)` 预分配保留节点 ID 池并下发给画布，低于阈值时补充。身份仍由宿主生成，符合 ADR 0005。
- 画布拆块时从池中取一个 ID，立即在 DOM 中建出新块并把光标移入；拆块动作携带该 `newNodeId`。现有 `createCanvasInputKernelOperation` 已支持由宿主提供新节点 ID。
- 宿主在会话边界校验：ID 属于当前桥会话与纪元的池，且未被任何操作消费；一经消费不再复用，拆块被拒也不复用；同一动作的重放与重试沿用同一 ID。内核只继续校验原有文档契约，不理解通信会话。
- 指向新块的后续动作由第 3 节保证：拆块被接受后目标才存在；拆块被拒，则依赖它的动作为 `cancelled` 并转为恢复记录。
- 池耗尽时 Shift+Enter 被阻止并明确反馈，**不排队，不设超时**。桥会话或纪元变化时池作废并重新下发。

### 8. 宿主变更与撤销等待

以下操作是宿主变更，产生的版本来源记为宿主：撤销、重做、源码替换、功能区结构操作、放弃修改、冲突后「保留本地草稿」（`keepEntryDocumentDraft`）、元数据与资产等影响预览的更新、双链候选落定。宿主先按序处理完已收到的全部画布动作，再施加变更，并更新 `lastForeignVersion`。切换文档与冲突后「载入最新版本」是纪元更新，按第 4 节处理。

画布发起的撤销与重做作为编辑动作进入序列。其结果无法乐观预测，因此在覆盖它的快照被挂载之前，画布进入**撤销等待**：

- 等待期间产生的编辑动作（插入文字、删除、换行、粘贴、组合提交）以规范化动作缓冲，并记录产生时的格式；缓冲绑定这一次撤销或重做动作，不缓冲原始按键。快照挂载后，缓冲动作在快照给出的落点（无落点时为当前光标）按序生成正式编辑动作。
- 等待期间的选区动作不在旧视图上执行（旧视图的位置在撤销后不可信）；等待提示说明光标移动尚未生效，快照挂载后光标取落点。
- 组合在等待期间被取消时不产生动作；组合提交则作为一个缓冲动作。
- 等待期间发生桥会话或纪元变化：缓冲动作全部转为恢复记录，归属原文档。
- 宿主超过可感知阈值仍未给出覆盖它的快照时，界面显示等待状态，并允许「取消等待」：缓冲动作转为恢复记录，此后不再自动重放；该撤销动作的快照若随后到达，仍按第 4 节挂载。不自动改投，也不只停留在内部诊断。

### 9. 选区恢复

重放负责恢复文档投影，不无条件决定当前光标。挂载与重放后按以下规则确定光标：

1. 若存在发生在最后一个重放编辑动作之后的作者选区动作，取其中最新者的位置；该位置仅当它之前的全部编辑动作都已被接受或已重放（即它所处的视图与当前视图相同）且节点仍在、偏移未越界时才有效。
2. 否则若有重放编辑动作，落在最后一个之后。
3. 否则若快照带有 `landing`，落在 `landing`。
4. 否则保持挂载前的语义位置，前提是该节点在挂载前后语义文本相同。
5. 以上都无法证明有效时，显式失效：清除文本光标、保留块选中，并在恢复提示中说明；不猜测位置。节点已不存在时同样清除，并按作者手势规则清除待输入标记。

### 10. 被取代的现有机制

以下机制由第 3 至 9 节取代：待确认输入期间推迟预览（仅保留组合期间）、成功回执丢弃暂存预览、拒绝回滚落点、拆块围栏及其超时重放、`resolve-input` 中的 DOM 决策。插入点锚点、末行占位、本地回显保留。

## 第一阶段交付

1. 画布侧会话状态机，与宿主侧会话层（内容版本、依赖判定、快照组装、终态保留与确认、保留 ID 池、撤销等待、恢复记录），均不依赖 DOM。
2. 事件序列测试：穿过实际宿主适配边界，调用真实内核（`createDocumentKernelDraftRuntime`），断言每一步画布应显示的文本、光标、格式与恢复记录，并断言最终与内核源码的语义文本收敛。至少覆盖：
   - 旧预览晚到（组合期间暂存后又收到更新快照）、重复快照、重复终态与未确认终态的重发；
   - 拒绝前序后的后续动作（`ab / X / Y` 反例须得到 `cancelled` 与恢复记录）；
   - 宿主变更期间仍在传输的旧底稿动作（第 5 节示例）、元数据变更推进版本；
   - 拆块后立即打字、连续拆块、拆块被拒、保留池耗尽；
   - 组合进行中到达快照、组合期间已收到 `accepted` 终态但尚未挂载、组合跨越一次拒绝；
   - 等待终态期间用户点击别处或切换待输入格式；
   - 撤销与继续输入交错、撤销栈为空、撤销等待中移动光标、取消等待、切换文档；
   - 冲突后「保留本地草稿」与「载入最新版本」；
   - 恢复记录：插入到当前光标的成功与失败、「输入后删除」的失败组；
   - 画布运行时重启后到达的旧会话消息。
3. 运行时替换放在第二阶段。

原生验收仍包含输入正确性：WebView 实际如何派发组合事件、保持焦点、恢复选区，都只能在原生环境确认（此前漏掉组合开始导致文字未提交即属此类），不得缩减为只检查闪色。

## 考虑过但不采用

**快照只携带水位线。** 水位线只说明处理进度，不能证明剩余动作可以原样重放，背景中的反例即为证明。

**以 `changeVersion` 作为快照版本。** 元数据等变化不推进它、载入最新版本使它归零，同一取值可对应不同预览。

**终态差量只以上一份已发送快照为裁剪依据。** 画布未挂载或未处理某份快照时会丢失终态；改为宿主保留、画布确认后裁剪。

**撤销等待期间缓冲原始按键。** 原始按键无法完整表达中文组合与粘贴；缓冲规范化编辑动作。
