# ADR 0007：画布输入会话的一致性契约

- 状态：待评审；第一阶段只交付本契约与可执行的事件序列测试，不替换运行时
- 日期：2026-09-22
- 关联：[ADR 0003](0003-page-document-canvas-isolation.md) 的 bridge 协议；[ADR 0005](0005-page-document-node-identity-and-component-contract.md) 的节点身份规则；[ADR 0006](0006-page-document-caret-and-inline-format.md) 的光标权威、行内格式、插入点锚点与末行占位

## 背景

ADR 0006 解决了「待输入标记归谁管理」，但一次输入从产生到落入文档的完整生命周期没有被设计过。文字依次经过输入法原生 DOM、画布乐观 DOM、内核提交后重新生成的预览；组合提交先还原组合前节点再重新插入；预览回来后整棵替换画布。内容、格式、焦点与光标要在这些交接中保持一致，而此前的做法是按症状追加推迟预览、丢弃暂存预览、拆块围栏与超时重放。

这些补偿依赖未经契约保证的假设，代码中可见的证据有四条：

1. **预览与输入回执没有版本关联。** 预览只有 `requestId/html/css`，回执只有 `intentId/accepted/selection`，消息 `sequence` 只表示通道顺序。「成功回执到达时暂存预览必然早于该次提交」是对当前宿主调度的观察，不是协议保证（`canvas/runtime/resolvedSelection.ts` 的 `settleCanvasInputRender`）。
2. **拒绝后原样重放不成立。** 权威文本 `ab`，输入 1 在偏移 1 插入 `X`（得 `aXb`），输入 2 在偏移 2 插入 `Y`（得 `aXYb`）。若输入 1 被拒、输入 2 仍待处理，在 `ab` 上原样重放输入 2 得到 `abY`；由于折叠范围的 `expected` 是空字符串，现有范围校验（`application/canvasInputOperation.ts` 的 `applyCanvasInputToText`）仍然通过。记录不变，不代表记录在新底稿上仍然成立。
3. **拆块围栏在超时后按当时的光标与当时的格式重放**（`canvas/runtime/structuralInputFence.ts` 与 `main.ts` 的重放逻辑），等待期间移动光标或改变格式时，先前输入的归属没有保障。
4. **宿主在接收时就到已提交源码中查找输入目标**（`hooks/useEntryPageDocumentSession.ts` 的 `applyCanvasInputIntent`），依赖尚未提交之结构的输入必然被拒。

现有测试多为单个状态对象的调用、队列的入队出队或源码字符串匹配，没有覆盖事件交错，因此不足以证明这些机制组合后稳定。

## 决策

采用「权威快照 + 本地重放」。宿主是唯一权威；画布挂载宿主快照后，把尚未得到终态、且依赖仍然成立的本地输入按序重新施加。以下各节是正确性契约，第一阶段须以事件序列测试证明。

### 1. 术语与版本

| 名称 | 含义 |
| --- | --- |
| 桥会话 | 现有 bridge 会话令牌，与画布 iframe 同生命周期；令牌不同的消息由现有闸门拒绝 |
| 文档纪元 `epoch` | 宿主会话状态被重新创建、修订号从零开始时递增：首次载入、切换文档、重新载入。放弃修改与冲突采纳在原状态上递增修订号，属于第 8 节的宿主变更，不更新纪元 |
| 草稿修订号 `revision` | 纪元内严格递增，每次草稿变化加一；现有 `changeVersion` 在状态重建时归零，因此必须与纪元成对使用 |
| 输入序号 `seq` | 画布在桥会话内为每个输入分配，严格递增 |
| 水位线 `watermark` | 宿主已按序处理完的最大 `seq`；不大于水位线的每个输入都已有终态 |
| 输入终态 | `accepted`（写入草稿）、`rejected`（所在批次未通过内核或宿主校验）、`cancelled`（依赖失败，未交给内核） |

一份快照由 `(epoch, revision)` 唯一标识。水位线相同的两份快照仍可能对应不同文档状态（中间发生了撤销或源码替换），因此画布不得只凭水位线判断快照新旧。

### 2. 输入记录

每个输入在产生时锁定，之后不再读取「那时的光标」或「那时的格式」：

- `seq`、输入类型、目标节点、`from/to/expected`、文字；
- 当时的待输入标记快照；
- 拆块输入的 `newNodeId`（来自第 7 节的保留池）；
- 依赖基线 `base = {epoch, revision, watermark}`：产生时画布已挂载快照的版本与水位线。

组合输入的目标、偏移、格式与依赖基线在组合开始时锁定，组合结束时只补上最终文字与 `seq`。

### 3. 依赖规则（宿主判定）

输入 `n` 可以交给内核，当且仅当同时满足：

1. `base.epoch` 等于当前纪元；
2. 自 `base.revision` 以来的每一次草稿修订，都由 `seq` 位于 `(base.watermark, n)` 区间内、终态为 `accepted` 的画布输入产生；
3. 该区间内没有 `rejected` 或 `cancelled` 的输入。

否则 `n` 的终态为 `cancelled`，不交给内核。直观地说：画布算出 `n` 的偏移时所看到的文档，必须恰好等于宿主处理 `n` 之前的草稿，任何「非本链路」的修订或前序失败都使偏移不可信。

补充规则：

- 目标节点的存在性在按序处理时校验，不在接收时校验。
- 同一内核请求中的输入是原子批次，终态相同；批次被拒则整批为 `rejected`，不得只确认其中一部分。
- **本轮不引入通用位置重算。** 无法证明可安全重放的依赖输入停止自动提交，转为第 6 节的可恢复内容。

### 4. 快照

快照取代现有 `render` 命令，字段为：`epoch`、`revision`、`watermark`、`outcomes`、`html`、`css`，以及仅用于宿主发起变更的可选 `landing`。

宿主保证：

- 每处理完一批画布输入或一次宿主变更，发出一份快照；
- `outcomes` 覆盖自上一份**已发送**快照的水位线（不含）到本快照水位线（含）之间每个输入的终态；
- bridge 通道先进先出，因此画布即使不挂载某份快照，也能按序收到全部终态。

画布接纳规则：

| 情况 | 处理 |
| --- | --- |
| `epoch` 更新 | 全部待确认输入转为可恢复内容，挂载新快照 |
| 同纪元、`revision` 更大 | 挂载并重放 |
| 同纪元、`revision` 相等 | 不因版本重挂；处理 `outcomes`，若有待确认输入被拒或取消，在已挂载快照上重建并重放其余输入 |
| 同纪元、`revision` 更小，或水位线回退 | 协议违例：忽略并记录诊断 |
| 组合输入进行中 | 只处理 `outcomes` 并记住最新快照；组合结束后再挂载 |

「更小的修订晚到」在先进先出通道上不应发生；组合期间暂存后又收到更新快照的情况，按上表只保留最新者。重复快照（例如一次拒绝触发多份相同预览）属于修订号相等的情形。

### 5. 重放

挂载快照后，按 `seq` 顺序重放 `seq` 大于其水位线的待确认输入，前提是该输入依赖区间内没有已知 `rejected/cancelled` 的输入；否则不重放，直接转为可恢复内容。重放使用输入记录中的格式快照。挂载与重放在同一任务中完成。

同步完成只保证不会画出中间状态的 DOM，**不作为「不闪烁」的证明**；绘制效果由原生验收确认。

### 6. 可恢复内容

`rejected` 与 `cancelled` 的输入从画布撤下，但文字不得丢弃：宿主保留「未写入内容」记录（文字、原目标节点、原偏移、原因），以非阻塞提示告知作者，并提供复制与「插入到当前光标」。后者是作者显式动作，不属于自动改投。

**禁止静默删除，禁止换个位置自动写入。**

### 7. 结构身份与乐观拆块

- 宿主会话层按 `(桥会话, 纪元)` 预分配保留节点 ID 池并下发给画布，低于阈值时补充。身份仍由宿主生成，符合 ADR 0005。
- 画布拆块时从池中取一个 ID，立即在 DOM 中建出新块并把光标移入；拆块输入携带该 `newNodeId`。现有 `createCanvasInputKernelOperation` 已支持由宿主提供新节点 ID。
- 宿主在会话边界校验：ID 属于当前桥会话与纪元的池，且未被任何操作消费；一经消费不再复用，拆块被拒也不复用；同一操作的重放与重试沿用同一 ID。内核只继续校验原有文档契约，不理解通信会话。
- 指向新块的后续输入由第 3 节保证：拆块被接受后目标才存在；拆块被拒，则依赖它的输入为 `cancelled` 并转为可恢复内容。
- 池耗尽时 Shift+Enter 被阻止并明确反馈，**不排队，不设超时**。纪元变化时池作废并重新下发。

### 8. 宿主发起的变更

撤销、重做、源码替换、功能区结构操作、放弃修改、冲突采纳、双链候选落定，一律视为屏障：

- 宿主先按序处理完已收到的全部画布输入，再施加变更；该修订记为非画布来源，使此前基于旧修订产生的画布输入在第 3 节中失败，转为可恢复内容。
- 画布发起的撤销与重做作为带 `seq` 的输入进入同一序列。由于其结果无法乐观预测，之后的按键在覆盖它的快照挂载前以原始按键暂存（尚未生成输入记录），挂载后在快照给出的落点生成输入。暂存没有超时改投；宿主若始终不给出覆盖它的快照，属于宿主缺陷，由诊断暴露。
- 切换文档与重新载入表现为纪元更新，按第 4 节处理；旧纪元的消息一律不再施加。

### 9. 选区恢复

挂载与重放后按以下优先级确定光标：

1. 有重放输入时，落在最后一个重放输入之后；
2. 否则快照带有 `landing` 时，落在 `landing`；
3. 否则保持挂载前的语义位置（同一节点且未越界）；
4. 节点已不存在时清空选区，并按作者手势规则清除待输入标记。

### 10. 被取代的现有机制

以下机制由第 3 至 9 节取代：待确认输入期间推迟预览（仅保留组合期间）、成功回执丢弃暂存预览、拒绝回滚落点、拆块围栏及其超时重放、`resolve-input` 中的 DOM 决策。插入点锚点、末行占位、本地回显保留。

## 第一阶段交付

1. 画布侧的会话状态机与宿主侧的会话适配逻辑（依赖判定、快照组装、保留 ID 池），均不依赖 DOM。
2. 事件序列测试：穿过实际宿主适配边界，调用真实内核（`createDocumentKernelDraftRuntime`），断言每一步画布应显示的文本、光标、格式，并断言最终与内核源码的语义文本收敛，避免只证明状态机按自己的假设运行。至少覆盖：
   - 旧预览晚到（组合期间暂存后又收到更新快照）、重复快照、重复回执；
   - 拒绝前序后重放后续（背景中的 `ab / X / Y` 反例必须得到 `cancelled` 与可恢复内容）；
   - 拆块后立即打字、连续拆块、拆块被拒、保留池耗尽；
   - 组合进行中到达快照、组合跨越一次拒绝；
   - 等待终态期间用户移动光标、切换待输入格式；
   - 撤销与继续输入交错、功能区变更与画布输入交错；
   - 会话重置（纪元更新）后到达的旧消息。
3. 运行时替换放在第二阶段。

原生验收仍包含输入正确性：WebView 实际如何派发组合事件、保持焦点、恢复选区，都只能在原生环境确认（此前漏掉组合开始导致文字未提交即属此类），不得缩减为只检查闪色。

## 考虑过但不采用

**快照只携带水位线。** 水位线只说明处理进度，不能证明剩余输入可以原样重放，背景中的反例即为证明。

**拒绝后按位置重算继续提交（操作变换）。** 正确实现需要对每类输入定义变换，本轮范围不容纳；依赖失败统一转为可恢复内容，今后如需要再单独立项。

**让内核理解保留 ID 池。** 保留池是通信会话概念，校验放在宿主会话边界；内核只校验文档契约。

**拆块等待期间按超时改投当前光标。** 已由第 7 节的乐观拆块取代；任何路径都不得重新引入「超时后改投当前位置」。
