# ADR 0004：统一对象层、受控引用与资产归属范围

- 状态：接受；对象层、资产范围、trigram 段落索引、项目打开重建与桌面快照/世界包后端迁移已实施，组件链授权、节点规则和跨平台验收仍未完成
- 日期：2026-09-18
- 修订：[ADR 0002](0002-page-document-storage.md) 中派生投影按记录存放、删除时由触发器写墓碑、回执按封闭作用域分组的部分，以及迁移 `0011_page_document_assets.sql` 中资产归属项目的做法。ADR 0002 的源码按领域对象分表、revision CAS 与幂等回执语义保持有效。

## 背景

ADR 0002 把页面源码放在与领域对象关联的独立记录中，避免了万能文档表。落地后，派生数据、删除记录和回执也随之按记录分散（`core_world_data` `007b6c8`）：

- `entry_page_documents` 与 `project_home_documents` 各自保存 `derived_text`；
- 只有词条页面有墓碑表，墓碑由 `AFTER DELETE` 触发器写入，`modified_by` 固定为 `system`，丢失了真正的删除者；
- `page_document_save_receipts` 以 `CHECK (scope IN ('entry','project_home'))` 限定作用域；
- `page_document_assets.project_id` 非空并随项目级联删除，`media_type` 以 `CHECK` 限定为 PNG、JPEG、WebP，画布按项目授权读取 `fcasset://`。

新的要求使这些形态不再适用：

- 页面需要引用公共组件，修改组件定义后，跟随最新修订的实例同步变化；页面真值因此包含对外部定义的引用。
- 世界观、大纲、小说、剧本等不同对象需要互相引用、按段落检索和对照；按记录分散的做法让每新增一种对象都要复制一套墓碑、派生文本、出链和回执。
- 后续多设备同步与合并需要统一的变更流、带删除者的可传播删除记录，以及节点级差异。
- 组件、模板和资产可能属于项目之外的范围（组件库、插件包、空间），资产绑定项目时只能逐项目复制。

页面文档契约 v1 尚未冻结（阶段 A 未退出），此时修订只需要迁移与测试；冻结后再改须升契约版本。

## 决策

### 1. 页面源码中的受控引用

页面源码（HTML/CSS）是页面表现层唯一可编辑的真值，源码中允许出现受控引用：

| 引用类型 | 源码表达 | 解析 |
| --- | --- | --- |
| 组件实例 | 受控元素，保存组件 ID、实例 ID、属性值、插槽内容与样式变量覆盖；序列化格式复用 `data-fc-*` 命名空间与现有模板插槽机制，阶段 A 冻结前定稿 | 宿主按组件定义修订展开 |
| 结构化事实绑定 | 现有 `data-fc-bind`（如 `title`、`summary`） | 宿主从领域数据读取 |
| 资产 | 现有 `data-fc-asset-id` 与 `fcasset://<uuid>` | 宿主沿引用链授权后读取 |
| 对象内链 | 现有 `fc://self/<种类>/<ID>` 文法；校验白名单按对象种类逐步放开 | 宿主路由到对应对象 |

规则：

- 引用由宿主在编译预览时解析；画布只接收展开并通过安全编译的结果，展开结果不回写源码。
- 引用目标或修订不存在时显示确定的缺失状态，不静默删除源码中的引用。
- 删除页面上的绑定元素不删除对应的领域事实。

### 2. 源码存储保持按领域对象分表

ADR 0002 的源码存储布局不变，仍不建万能文档源码表，不为未来对象种类建空表。

### 3. 统一对象层

身份、引用、派生索引、删除记录、变更记录与保存回执统一为一层，由所有对象种类共用。迁移 `0012_object_layer.sql`、`0014_asset_scopes.sql`、`0015_object_text_fts.sql` 和 `0016_object_text_trigram.sql` 已将首批表名与关键字段定稿；0016 重建了 0015 的 `unicode61` 旧索引，以与 `entries_fts` 相同的 trigram 语义支持中文子串：

| 已实施表 | 关键字段 | 作用 |
| --- | --- | --- |
| `local_spaces` | `id`、`name`；`projects.space_id` 指向本地默认空间 | 项目空间落点，尚无跨设备空间管理 |
| `object_registry` | `id`（16 字节 UUID，主键）、`kind`、`project_id`、`deleted_revision`、`deleted_at`、`deleted_by`、`cascade_source_id`、`created_at` | 对象登记；对象删除后保留该行并标记删除，作为墓碑 |
| `object_references` | `source_id`、非空哨兵 `source_node_id`、`target_id`、非空哨兵 `target_node_id`、`ref_type`、`source_revision` | 内链与资产引用；组件实例引用尚未接入 |
| `object_text_blocks` / `object_text_blocks_fts` | 显式 `block_rowid`、`object_id`、`node_id`、`ord`、`text`、`revision` | 段落级派生索引与 FTS；旧页面在应用重建前由 `object_legacy_text` 保底 |
| `object_changes` | `seq`（自增）、`object_id`、`kind`、`revision`、`change_type`、`actor`、`source`、`at` | 本地变更流 |
| `object_save_receipts` | `kind`、`object_id`、`request_key`、`request_hash`、`receipt_json`、`created_at` | 开放对象种类的幂等回执，每目标仍保留最新 64 条 |
| `page_document_assets` / `asset_scopes` | 资产身份与内容事实；`asset_id`、`scope_kind`、`scope_id`、`added_at` | 同一原件可登记多个项目范围；当前只授权项目范围 |

约束：

- **对象 ID 跨种类全局唯一**，沿用现有 16 字节 UUID；引用只凭对象 ID 即可定位，`kind` 用于路由到领域服务。
- **对象种类是开放集合**：已知种类登记在 Rust 代码中，由领域服务校验；数据库不写 `CHECK` 枚举，因为 SQLite 修改 `CHECK` 只能重建表。读取端遇到未知种类（例如由较新版本同步或导入而来），按不透明对象保留，不渲染、不执行。
- **只登记已进入纵向实现的种类**：首批为 `project`、`entry`、`project_home`；`component_definition` 在组件落地时登记。
- **可空的节点列参与唯一约束时使用确定的哨兵值**：SQLite 唯一约束中的 NULL 互不相等，直接使用 NULL 会产生重复引用。
- **全文检索以显式 INTEGER 行键关联段落表**，不依赖 BLOB 主键表的隐式 `rowid`（工作区开发记录「FTS5 隐式 rowid 错位」）；过滤条件放在正确的层（「FTS 过滤放错层」）。
- **派生数据只由已校验源码生成**，与源码在同一事务提交；重建派生数据不改变源码与 revision。
- **长查询先取有界 FTS 候选再回主表**，项目过滤与排序不放进 FTS 虚表。两字以内仍用 `LIKE`；项目打开时只为缺段落块的页面补建投影，命令回执给出成功与跳过数。

### 4. 删除走领域命令并记录真实删除者

删除由领域命令在一个事务内完成：为被删对象及其级联子对象逐一在 `object_registry` 标记删除修订、删除时间与发起操作的主体，写入 `object_changes`，再删除源码与领域数据行。数据库触发器只做兜底：`BEFORE DELETE` 时若对应登记行尚未标记删除，则 `RAISE(ABORT)`。触发器不再代写墓碑，也不再使用 `system` 作为删除者。

### 5. 节点身份的保持与重映射

页面源码中的 `data-fc-node-id` 与 `data-fc-node-kind` 是段落级索引、引用到段落、差异对照和后续按节点合并的共同基础。以下规则写入页面文档契约 v1，并有自动化测试：

| 场景 | 规则 |
| --- | --- |
| 保存、撤销、重做 | 未改动节点保留 ID；撤销恢复原 ID |
| 可视编辑与源码编辑 | 修改内容不换 ID；新增节点分配新 ID；源码编辑后缺失 ID 的节点在保存时补新 ID；重复 ID 保留文档顺序中的第一个，其余分配新 ID 并给出诊断 |
| 拆分与合并段落 | 拆分时前半保留原 ID、后半分配新 ID；合并时保留前一节点的 ID，指向被并入节点的引用改指合并后的节点 |
| 同文档复制粘贴 | 复制产生新 ID；剪切移动保留原 ID |
| 跨文档粘贴 | 一律分配新 ID |
| AI 候选 | 必须保留未改动节点的 ID；新增节点由宿主分配 ID；候选中出现已存在的 ID 但节点种类不符时拒绝该候选 |
| 组件实例 | 实例本身是一个页面节点，另有实例 ID；组件内部节点不进入页面节点身份体系 |
| 转为本地组件 | 展开的内部节点分配新的页面节点 ID；实例 ID 退役，指向实例的引用改指展开后的根节点 |
| 删除节点 | ID 不复用；指向该节点的引用降级为对象级引用，并在引用表中标记 |

节点 ID 在单个文档内唯一；跨对象引用使用「对象 ID + 节点 ID」。

### 6. 资产身份与归属范围分离

- 资产记录只保存身份与内容事实：资产 ID、媒体类型、字节数、内容摘要、尺寸与当前原件布局，去掉 `project_id`。处理版本和原件/派生关系尚未进入本次表结构。
- 归属范围单独记录于 `asset_scopes`（`asset_id`、`scope_kind`、`scope_id`、`added_at`），一个资产可以属于多个范围。首批只实现项目范围，范围种类按开放集合设计。
- 页面与组件对资产的使用记入 `object_references`，`ref_type` 为资产引用。
- 当前画布读取和保存按文档所在项目的资产范围授权，草稿新图在引用落库前也可读取；组件落地后须扩展为「当前文档 → 组件实例 → 组件定义 → 资产」逐段授权，不得只凭引用记录授权。
- 资产在某范围内不再被引用、且被移出该范围时方可解除归属；所有范围都解除后才允许清理原件与派生表示。项目删除路径仅清理本次失去最后范围的资产记录；桌面命令在检查主库和其余世界库的范围及引用、重新核验原件后才清理共享文件。检查失败或原件损坏时保留文件并报告，避免误删共享原件。世界包覆盖与独立范围撤销尚未统一接入这条磁盘清理路径。
- 媒体类型允许集合由 Rust 校验，不写数据库 `CHECK`。

### 7. 层叠顺序与最低系统版本

组件样式并入画布现有的 `@layer` 层序：组件默认样式位于画布主题默认值之上、项目主题层（`fc-project`）之下；实例覆写位于项目主题之上；作者高级 CSS 最高。[ADR 0003](0003-page-document-canvas-isolation.md) 中未分层的运行时安全规则保持不变。具体层名与 ADR 0003 的现有层序合并定稿，不以 `!important` 作为覆写机制。

`@layer` 需要 Safari 15.4 及以上的 WebKit，对应 macOS 12.3，而当前 macOS 最低支持版本为 12.0。阶段 A 退出前须二选一：提高最低版本到 12.3，或在 12.0–12.2 且未更新 Safari 的系统上实测画布样式优先级。不以较新系统上的原生验收结果代替。

## 后果

- `core_world_data` 已以增量迁移接收 0010、0011 的派生文本、墓碑、回执和资产数据；默认特性与 SQLite 最小特性两条全量测试链通过。组件定义尚无领域实现，不在本次迁移范围。
- `app_main` Rust 校验已输出段落块与引用集合，保存及项目打开时的缺块重建可更新 trigram FTS；资产读取与保存目前按项目范围授权，组件链授权仍待组件落地。
- 删除词条、项目等操作已走领域命令；直接 SQL 删除由 `BEFORE DELETE` 触发器拒绝。桌面快照、CSV 与版本化 `.fcworld` 已带对象层载荷；旧快照和旧包仍可读取。
- 快照的对象层载荷不再保存变更流和幂等回执，恢复也不回放旧载荷里的变更流；恢复产生新的变更事件，旧回执失效。合成测试中对象层 JSON 从 737 字节降为 382 字节（2026-09-18 本机实测，1 条变更与 1 条回执），实际快照体积随历史长度而变；世界包导出仍保留现有字段。
- 代价：每次保存都要重建该对象的段落块与引用，写入量增加；对象种类开放后，数据库不再兜底枚举合法性，合法性由领域服务与测试保证。

## 备选方案

- **保持 ADR 0002 按记录分散派生数据**：每新增一种对象都要复制墓碑、派生文本、出链与回执，后续同步与合并需要拼接多张表。不采用。
- **万能文档源码表**：ADR 0002 否决它的理由（删除、权限边界、迁移与快照按领域外键表达）仍然成立。不采用。
- **资产全局唯一但不记录范围**：无法判断何时可以清理，也无法按范围授权。不采用。
- **继续由触发器写墓碑**：触发器拿不到发起删除的主体。不采用。
