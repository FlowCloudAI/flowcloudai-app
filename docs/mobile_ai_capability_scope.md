# 移动端 AI 能力范围与已知取舍

> 状态：现行 ｜ 日期：2026-08-30 ｜ 适用：`app_main` 移动端（`src/app/mobile/**`）

本文只回答一件事：**移动端 AI 相比桌面端，哪些能力是有意不做的，为什么。**

背景是 2026-08-30 的一次逐项比对——`useAiController` 暴露的 `AiContextValue` 是两端共享的完整契约，
桌面 `AIChatContent.tsx` 几乎全量消费，移动端只消费了一部分。比对把差距分成三类：**该补的**（已按序补齐，见
下方「已补齐」）、**有意不做的**（本文主体）、**两端都没接的**。没有本文的话，同样的差距会被反复重新发现、
反复重新讨论。

## 1. 有意不做

### 1.1 指令能力（应用感知自定义指令、指令模板、对话级独有提示词）

**结论：移动端不提供任何指令编辑入口。桌面端不受影响。**

2026-08-29 移除了移动端设置的「指令模板」页，同时撤掉了 AI「更多」面板里的「当前对话独有提示词」输入框。
现在移动端没有入口可以编辑：

| 能力 | 数据字段 | 桌面端入口 |
| --- | --- | --- |
| 应用感知自定义指令 | `settings.llm.app_sense_custom_prompt` | 设置 → 指令模板 |
| 指令模板文件 | `template_*` 系列命令 | 设置 → 指令模板 |
| 对话级独有提示词 | `Conversation.settings.systemPrompt` | 对话属性面板 |

理由有两层。表层是这三项都要求在手机上编辑多行、结构化、容易改坏的文本，而
`designs/mobile-ui-baseline.md` §9 规则 8 已经把「需要输入的内容」挡在底部面板之外，真要做就得为它们各开一个
完整页面。深层是这三项都会**静默改变每一次对话的行为**：在小屏上编辑一段看不全的指令，出问题时很难归因，
而手机上又缺少桌面端那种「改完立刻在长对话里回读验证」的条件。

**数据一侧没有动。** 三个字段仍然存在、仍然生效、仍然由桌面端读写；移动端只是不显示、不编辑。
在桌面配好的指令，在手机上照常起作用。

### 1.2 分支切换

**结论：暂不做，两端都不做。**

`AiContextValue` 里有 `getBranchInfo` 与 `switchBranch`，`MessageBox` 也已经具备分支导航的渲染能力
（`showBranchNav` + 上一个/下一个按钮）。但**两端都没有任何 UI 消费它们**——桌面端同样没有。

也就是说：重说（`regenerateMessage`）会在数据层产生分支，但两端都没有回到旧分支的入口。这不是移动端欠桌面端
的债，是整个产品欠的债。移动端单独做会造成「手机能翻分支、电脑不能」的反向割裂，所以一并压后。

真要做的时候，两端应当一起做，并且先确定分支在会话列表与导出里怎么表达。

### 1.3 工具面板（用户手动勾选可用工具）

**结论：不做。**

`AiContextValue` 暴露了 `tools: ToolStatus[]`，两端都没有界面消费。曾经的设想是给用户一个面板逐个勾选
本次会话允许使用哪些工具。不做的原因是它与既有的**工具权限模式**（读者 / 助手 / 作家，见输入卡上的模式胶囊）
重叠：权限模式已经用三档语义覆盖了「能不能读、能不能写、写要不要确认」，再叠一层逐工具开关，等于让用户
在两套心智模型之间对齐，而两者冲突时的优先级又需要额外规则。

`tools` 字段保留，供将来做**只读的**工具可用性展示（例如提示某个工具因插件缺失而不可用），但不做成用户开关。

### 1.4 相机 / 图库

**结论：保留「即将支持」占位，暂不实现。**

AI「更多」面板里的相机与图库按钮是 `disabled` 状态的占位。保留占位是有意的——它表达了后续会做，
而不是这条路走不通。与之相对，输入框原来的「按住说话」占位已在 2026-08-30 撤掉：全仓没有任何语音输入实现，
那句文案承诺的是一个不存在的能力，和「即将支持」这种明确标注不同。

## 2. 已补齐（2026-08-29 ~ 08-30）

列在这里是为了说明本文第 1 节的取舍不是「移动端做不动」，而是逐项判断的结果。

- AI 回复的词条链接渲染与锚点接管（`[[标题]]` / `fc://` / `entry://` 不再是死链）
- 消息级操作：复制 / 重说 / 编辑
- 已引用文档的列表、移除与重新解析
- 对话记忆用量环（默认只画环，点击展开数值浮窗）
- 角色对话入口与角色背景

## 3. 复核提示

本文的结论建立在 2026-08-30 的代码状态上。以下任一情况发生时需要重新评估：

- `MessageBox` 的分支导航在桌面端被接上——那时 §1.2 的「两端一起做」前提就变了；
- 工具权限模式被改成非三档语义——§1.3 的重叠理由随之失效；
- 移动端出现了适合承载长文本编辑的通用页面骨架——§1.1 的表层理由会消失，但深层理由仍在。
