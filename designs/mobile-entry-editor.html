移动端词条编辑态

入口：项目 Tab → 词条列表/项目主页 → 词条详情 → 编辑；新建词条直接落到本页。 底部 Tab 栏在这些页面始终存在（MobileApp.tsx 无条件渲染 MobileNav），画布中已如实画出。

本稿覆盖编辑态及其下级页面（属性页、关系编辑页、全屏专注）。查看态在 mobile-entry-detail.html，AI 讨论与差异审阅在 mobile-ai-entry-review.html，不在此拼合。

本轮改了什么

上一版把正文降级成一个按钮（现网实现 MobileEntryDetailEditView.tsx 的「正文」一节只有标题行 + 32px 的「沉浸编辑」）。本轮把正文放回页面主体，元数据移到独立的属性页， 关系编辑再下一级为移动端专用页面。

设计取舍

正文占主体，不再是一个按钮

编辑页第一屏就能读到并直接修改正文。「全屏专注」降级为可选入口（正文区右上 ⤢），不再是唯一通路。

整页不滚动，只有正文区自己滚

这是 2026-08-03 撤掉内联正文（c8973ec）的直接原因所在：表单整页滚动 + 内嵌可增高编辑器， 键盘一弹就失控。改成固定骨架后，键盘只需压缩正文区高度，与 AI composer 走同一条 --fc-kb 路径，符合 AGENTS.md §5.1「键盘只有一个 owner」。

元数据进独立的属性页，不用底部面板

属性内容既会超高滚动（类型 + 分类 + 图片 + 标签 + 关系），又全都需要输入， 两条都撞上「底部面板不承载滚动或输入内容」的规范。它是页面栈里的真页面（不是 Overlay）， 因此有真正的边缘返回手势、转场和返回键处理。规范条文见 designs/mobile-ui-baseline.md §9.8。

关系编辑是移动端专用的第三级页面

不再把桌面端 EntryRelationCreator 用 CSS 掰成竖排。关系页一页装下 目标词条搜索、方向分段和关系说明——正因为它是完整页面，滚动和输入都不再是问题。

草稿走 store，不靠 props 穿三层

编辑页 → 属性页 → 关系页共享同一份词条草稿。按 AGENTS.md §5.1，跨页共享状态走 useSyncExternalStore 式 store，不新增 CustomEvent。 store 生命周期 = 一次编辑会话，退出编辑态即清空。

摘要常驻三行

沿用 2026-08-03「摘要属于核心内容」的结论。2026-08-24 反馈明确：单行不可接受，至少三行。

全屏专注不带预览

专注模式的定位就是只写不看；要看渲染就收起回内联正文区切「预览」。避免同一个开关出现在两层。

正文区内建 编辑 / 预览 切换

现状是要看渲染效果必须「保存 → 退沉浸 → 退编辑态 → 回查看态」。 MarkdownEditor 已有 mode: 'edit' | 'preview'，这里只是把它接出来。

保留查看 / 编辑两态与手动保存

合并成单页直接编辑（自动保存）收益更大，但要重写 694 行的 MobileEntryDetail.tsx， 并触碰刚在 2026-08-23/24 稳定下来的键盘链路。本轮不动。

正文有容器，空状态不是一片死白

2026-08-24 Android 真机核对：正文原本只有上下分隔线、无容器，空词条时是一大片留白， 而次要的摘要反而带边框，主次颠倒。正文改为带边框与抬升底色的容器。

所有主入口回到 48px

--mobile-tap-min: 3rem 是项目自己的标尺。现状「沉浸编辑」32px、「新建类型」约 20px， 本稿内所有可点区域按 48px 画。

新建词条对齐桌面端的占位清理

桌面端 ProjectEditor.tsx 同样预先落库，但用 placeholderEntryIds 标记， 保存成功即清标记，关闭标签页时标记还在就删。其注释明确写了 不要按字段内容猜测空词条（只设了类型或关系的词条是有效的）。 移动端只抄了预创建、漏了清理。本稿按桌面端机制补齐：退出词条页时占位仍在就删。

待确认：分类回显要改另一份稿

查看态从未渲染分类（MobileEntryDetailView 无 category）。修法在 mobile-entry-detail.html，不在本稿范围内。

待确认：属性页是否需要「完成」按钮

本稿的属性页改动即时写回草稿，靠返回退出，没有「完成」。若要与编辑页的手动保存心智一致， 可以加一个只做返回的「完成」——但那是个假动作按钮，我倾向不加。
