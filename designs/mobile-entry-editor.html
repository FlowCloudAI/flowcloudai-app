相对现状的改动

  • 元数据整体移到正文之上。旧版把「类型/分类/标签/图片/关系」压成一行截断的 chips 放在正文下方。现在顺序是：身份（标题·类型·分类·摘要）→ 附件（图片·标签·关系）→ 正文，与桌面端 EntryEditorMetaPanel 在正文之上一致。
  • 类型与分类直接在身份区可改。它们回答「这条词条是什么」，不该和图片、关系一起藏进二级页。
  • 图片在编辑主页可直接增删。旧版必须进属性页才能加图。
  • 正文头部从 48px 压到 40px。分段控件视觉 28px、命中区用 ::after 补到 48px——基线 §6.1 规则 2 要求的是扩热区，不是放大视觉；旧版直接把 min-height 设成 48px 撑满整行（那是我上一轮为满足触控尺寸做的错误处理）。同样的做法用在类型 chips 与身份区的类型/分类选择器上。
  • 保存改为文字按钮。旧版是软盘图标，且 saving 时把图标换成「⋯」冒充 loading。左侧的返回箭头也改成「取消」，与离开守卫的语义一致。
  • 属性页改成 iOS 分组列表。行高 52px，标签一行一条（名称左 / 值右）。旧版每条标签是「名称 + 植入徽章 + 类型徽章 + 建议范围 + 输入框 + 清空」的复合卡，真机一屏只放得下 2 条。
  • 取消「植入」徽章。改为分组标题「「人物」的类型属性」与「其他标签」；植入标签不显示删除按钮，本身就是区别。
  • 取值范围提示只在真有边界时显示。旧版对默认范围也渲染「建议范围 0 - 不限」，一句零信息占一整行。
  • 类型 chips 换行而不是横滚。真机上「物品」被硬切在屏幕边缘，无渐隐无滚动条。换行后没有隐藏内容，也不需要 data-mobile-horizontal-scroll。
  • 「清空」只在有值时出现。旧版对空输入框也常驻一个「清空」按钮。

需要你确认

  • 元数据上移的代价在正文高度上。本稿实测（设计稿画布，非真机）：
    390×844 → 身份 209px、附件 62px、正文可视 323px（约 7 行）；
    360×740 → 身份 209px、附件 62px、正文可视 219px（约 4 行）。
    点进正文后身份与附件折叠，正文分别回到约 660px / 560px。 小屏 219px 是这套排版最薄弱的一处，要不要接受，或者在 <740px 高度时默认折叠附件条。
  • 附件条的图片缩略图仍是横滚（图多时）。它是本稿里唯一保留的横滚区，需保留 data-mobile-horizontal-scroll 标记。
  • 编辑态预览里的双链目前只提示不跳转（2026-08-25 修复顶层导航时的取舍）。要不要改成「保存并跳转」。
  • 属性页的关系仍在最下方——它是唯一真正属于「附件」的东西，且条目可能很多。
