# 设计稿约定

> 状态：现行 ｜ 日期：2026-09-13
>
> 由 `app_main/AGENTS.md`「界面设计稿约定」迁入。何时需要先出设计稿仍以 `AGENTS.md`「设计稿」为准，本文只管怎么做。

- 不默认使用 Figma 或其他外部设计工具，也不以聊天中的图片生成结果、文字描述或临时原型代替；只有用户明确要求图片方案时才用图片稿。除非用户指定，设计稿统一保存到 `app_main/designs/<主题名>.html`，不放临时目录或 `.codex/visualizations/`。
- 每份设计稿是能直接编辑、通过 `file://` 打开的单文件 HTML：CSS 与少量必要 JavaScript 全部内联，不依赖构建步骤、包管理器、CDN、网络资源或额外素材文件。
- 设计稿用于确认最终布局与交互，不是一次性线框图：表达真实的信息层级、主要组件、宽屏与窄屏状态及关键交互；内容可以精简，但不能省略影响设计判断的区域。
- 设计前先核对真实入口、所属 Tab、触发动作和背后页面。不同 Tab、不同业务板块或不会同时出现的状态拆成独立设计稿，不为展示方便拼进同一界面；浮层稿用它实际出现时的页面作背景。
- 同一方案的后续反馈原地修改同一个 HTML 文件；除非用户要求对比多个方向，不为每轮反馈复制新文件。
- 用 CSS 自定义属性模拟 `--fc-*` 语义令牌，保持与应用主题、圆角、间距和控件密度一致；不在设计稿中复制生产组件实现或业务逻辑。
- **设计 QA 的截图、矢量源等证据必须提交进仓库**，统一放 `designs/audits/<主题>-<日期>/`。指向仓库外临时目录（`.codex/`、系统 Temp、其他机器的用户目录）的证据等于没有证据——2026-08 已有 5 篇设计 QA 因此失去可复核性。
- 交付时给出文件路径并列出需要用户确认的关键点。确认后按该文件实现；实现中必须偏离已确认设计时，先说明原因和影响。
