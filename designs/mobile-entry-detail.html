展示态：相对现状的改动

  • 图片升为主视觉。原本是标题下方一条 88px 缩略图，且点不开（--static 无 onClick，查看态根本没挂灯箱）。改为 16:10 主图，右下角标张数，点击进设定集。对齐桌面端 entry-editor-cover-panel。
  • 类型与分类上移到标题正下方。原本类型徽章排在摘要之后，分类从来没显示过。现在「类型 · 分类 · 更新时间」一行，摘要在其后。
  • 属性从卡片改成定义列表。原本每个标签是带徽章、提示与值的卡片，一屏放两个。现在单行「名称 → 值」，行高 46px。
  • 用分组代替「植入」徽章。现状唯一区别是 4px 左蓝边（HighLightTagItem.css 的 .is-show.is-implanted），和未填写卡片长得一样，且「植入」是内部术语。改为「「人物」的类型属性」与「其他标签」两个分组。桌面端同样没解决这个问题，不值得照抄。
  • 未填写属性默认折叠。browseVisibleTagSchemas 会把未填写的植入标签也算进来，真机上三张「未填写」大卡吃掉整个元信息区。
  • 空正文给出主操作。基线 §9 规则 5 明令「空状态必须包含主操作本身」；现状只有一行「暂无正文内容」浮在 362px 高的空白里（真机实测，834px 视口占 43%）。
  • 顶栏滚动后显示词条名。长文滚动后原本只剩三个图标。
  • 编辑按钮改为实心填充。现状靠 kind:\'add\' 的 font-size 区分，但子元素是固定尺寸 SVG，真机实测三个按钮完全一致（48×48 按钮 / 23×23 图标 / 同色）。

编辑态：相对现状的改动

  • 元数据整体移到正文之上。旧版把「类型/分类/标签/图片/关系」压成一行截断的 chips 放在正文下方。新顺序：身份（标题·类型·分类·摘要）→ 附件（图片·标签·关系）→ 正文，与桌面端 EntryEditorMetaPanel 在正文之上一致。
  • 类型与分类直接在身份区可改。它们回答「这条词条是什么」，不该和图片、关系一起藏进二级页。
  • 图片在编辑主页可直接增删。旧版必须进属性页才能加图。添加位固定在缩略图条最前，避免被横滚滚出可视范围。
  • 正文头部从 48px 压到 40px。分段控件视觉 28px、命中区用 ::after 补到 48px——基线 §6.1 规则 2 要求的是扩热区，不是放大视觉；旧版直接把 min-height 设成 48px 撑满整行（那是上一轮为满足触控尺寸做的错误处理）。同样做法用在类型 chips 与身份区的类型/分类选择器上。
  • 保存改为文字按钮。旧版是软盘图标，且 saving 时把图标换成「⋯」冒充 loading。左侧返回箭头改成「取消」，与离开守卫的语义一致。
  • 属性页改成 iOS 分组列表。行高 52px，标签一行一条（名称左 / 值右）。旧版每条标签是「名称 + 植入徽章 + 类型徽章 + 建议范围 + 输入框 + 清空」的复合卡，真机一屏只放得下 2 条。
  • 取值范围提示只在真有边界时显示。旧版对默认范围也渲染「建议范围 0 - 不限」，一句零信息占一整行。
  • 类型 chips 换行而不是横滚。真机上「物品」被硬切在屏幕边缘，无渐隐无滚动条。换行后没有隐藏内容。
  • 「清空」只在有值时出现。旧版对空输入框也常驻一个「清空」按钮。

需要你确认

  • 元数据上移的代价在正文高度上。本稿实测（设计稿画布，非真机）：
    390×844 → 身份 209px、附件 62px、正文可视 323px（约 7 行）；
    360×740 → 身份 209px、附件 62px、正文可视 219px（约 4 行）。
    点进正文后身份与附件折叠，正文分别回到约 660px / 560px。 小屏 219px 是这套排版最薄弱的一处，要不要接受，或者在 <740px 高度时默认折叠附件条。
  • 展示态没有主图时完全不占位（见「无图片」状态），还是留一个可点的添加位。
  • 「更新于」用绝对日期还是相对时间。本稿用绝对日期，列表页用的是相对时间，两处会不一致。
  • 展示态的关联区故意不给「添加关系」入口——保持只读，加关系走编辑态，避免旧版「查看页其实是个表单」的滑坡。
  • 编辑态预览里的双链目前只提示不跳转（2026-08-25 修复顶层导航时的取舍）。要不要改成「保存并跳转」。
  • 属性页的关系仍在最下方——它是唯一真正属于「附件」的东西，且条目可能很多。
